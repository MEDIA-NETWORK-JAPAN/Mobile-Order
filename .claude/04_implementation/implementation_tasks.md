## 🎯 Phase 1 実装範囲分析

### 基盤要件
- **認証システム**: 4つの認証方式（Laravel Breeze、席セッション、ゲストセッション、Laravel Sanctum）
- **データベース**: 統一商品マスター設計
- **セッション管理**: 2層認証システム（第1層：席セッション、第2層：ゲストセッション）
- **カート管理**: Redis + DBハイブリッド管理（Redis guest_cart:{token} + cart_logsテーブル）
- **多言語対応**: JSON翻訳基盤

## ⚠️ 実装上の重要な注意点

### データベース設計での重要判断
1. **マイナス価格対応**: 値引き商品のため price フィールドはマイナス値許可
2. **統一商品マスター**: メイン商品・オプション商品を products テーブルで統一管理
3. **2層認証必須**: session_id（席共有）+ guest_token（個人識別）の両方が必須
4. **cloud_synced フラグ**: 障害復旧のためのシンプル同期管理
5. **availability_status**: ENUM型で4状態管理（available/sold_out/not_arrived/preparing）

### 設計書との整合性チェックポイント
- **テーブル構造**: `.claude/01_development_docs/02_database_design.md` に完全準拠
- **API仕様**: `.claude/01_development_docs/03_api_design.md` の契約遵守
- **認証方式**: `.claude/01_development_docs/13_auth_authorization_design.md` の3層認証実装
- **エラーハンドリング**: `.claude/01_development_docs/05_error_handling_design.md` のメッセージ体系

### 実装品質基準
- **95%以上の確信**: 各実装開始前に設計書を熟読し、不明点は質問で解決
- **1機能ずつ実装**: 複数機能の同時実装は禁止
- **コード+解説提示**: 実装完了時は必ずコードと解説をセットで提示
- **許可制**: 提示した内容への許可を得てから次の作業に進む
