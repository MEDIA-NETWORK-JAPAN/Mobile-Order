## 📋 Phase 1: 基盤構築の詳細解説

### 🌐 ネットワーク構築
各ネットワーク要素がMobile Order Systemでどのような役割を果たすか

#### **VPC作成 (mobile-order-vpc: 10.0.0.0/16)**
- **目的**: Mobile Order System専用の仮想ネットワーク空間を作成
- **重要性**: ⭐⭐⭐⭐⭐ 必須
- **詳細**: 
  - 他のAWSアカウント・システムから完全分離
  - セキュリティ境界の確立
  - 65,536個のIPアドレスを確保（将来拡張対応）

#### **パブリックサブネット作成 (2AZ)**
- **目的**: インターネットからアクセス可能な領域
- **重要性**: ⭐⭐⭐⭐⭐ 必須（ALB配置用）
- **10.0.1.0/24 (ap-northeast-1a)**: ALB用プライマリ
- **10.0.2.0/24 (ap-northeast-1c)**: ALB用セカンダリ（障害時冗長性）
- **なぜ2AZ**: 1つのAZが障害時、もう1つで継続運用

#### **プライベートサブネット作成 (4個)**
- **目的**: 外部からアクセスできない安全な領域
- **重要性**: ⭐⭐⭐⭐⭐ 必須（セキュリティの要）

**ECS用サブネット**:
- **10.0.11.0/24 (1a)**: Laravel アプリケーション実行
- **10.0.12.0/24 (1c)**: 冗長性確保
- **なぜ必要**: お客様の注文データ処理を外部から保護

**RDS/Redis用サブネット**:
- **10.0.21.0/24 (1a)**: データベース・キャッシュ
- **10.0.22.0/24 (1c)**: 冗長性確保
- **なぜ別分け**: データレイヤーのさらなる保護強化

#### **インターネットゲートウェイ作成・アタッチ**
- **目的**: VPCとインターネットの接続点
- **重要性**: ⭐⭐⭐⭐⭐ 必須
- **詳細**: お客様がQRコードからアクセスするために必要

#### **NATゲートウェイ作成**
- **目的**: プライベートサブネット→インターネット（一方向）
- **重要性**: ⭐⭐⭐⭐ 高い
- **なぜ必要**: 
  - ECSコンテナが外部APIを呼び出し（POS連携等）
  - パッケージ更新、セキュリティパッチ適用
  - ECRからDockerイメージ取得

#### **ルートテーブル設定**
- **目的**: ネットワーク通信の経路制御
- **重要性**: ⭐⭐⭐⭐⭐ 必須
- **設定内容**:
  - パブリック: インターネットゲートウェイ経由
  - プライベート: NATゲートウェイ経由

#### **セキュリティグループ作成**
各セキュリティグループの役割とMobile Order Systemでの使用場面

**ALB用 (80/443許可)**:
- **目的**: お客様のHTTPS/HTTPアクセスを受信
- **重要性**: ⭐⭐⭐⭐⭐ 必須
- **シナリオ**: 
  ```
  お客様がQRコードスキャン
  → https://order.your-restaurant.com
  → ALBが受信 → ECSに転送
  ```

**ECS用 (ALBからのみ許可)**:
- **目的**: アプリケーションへのアクセス制限
- **重要性**: ⭐⭐⭐⭐⭐ 必須（セキュリティの要）
- **なぜALBのみ**: 直接アクセスを防止、負荷分散経由のみ

**RDS用 (3306, ECSからのみ)**:
- **目的**: データベースアクセスの厳格制御
- **重要性**: ⭐⭐⭐⭐⭐ 必須（データ保護）
- **シナリオ**: 
  ```
  お客様の注文データ保存
  ECSアプリ → MySQL(3306) → 注文テーブル書き込み
  ```

**Redis用 (6379, ECSからのみ)**:
- **目的**: セッション・キャッシュデータの保護
- **重要性**: ⭐⭐⭐⭐⭐ 必須（セッション管理の要）
- **シナリオ**:
  ```
  カート情報の高速読み書き
  ECSアプリ → Redis(6379) → カートデータ更新
  ```

- **目的**: Mobile Order System専用DB準備

高速セッション・キャッシュ管理の中核

- **目的**: Redisクラスターの配置場所指定
- **重要性**: ⭐⭐⭐⭐ 高い

- **設計**:
