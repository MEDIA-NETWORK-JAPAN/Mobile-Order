# 非機能要件定義書

## 1. 概要

### 1.1 目的
本書はモバイルオーダーシステムの非機能要件（パフォーマンス、セキュリティ、可用性、保守性等）を定義し、システムの品質目標を明確にします。

### 1.2 適用範囲
- Web管理画面
- モバイルAPI
- POS連携API
- データベース
- インフラストラクチャ

## 2. パフォーマンス要件

### 2.1 レスポンス時間

#### Web管理画面
- **ページ読み込み**: 2秒以内
- **データ更新**: 3秒以内
- **レポート生成**: 10秒以内

#### モバイルAPI
- **メニュー一覧**: 500ms以内
- **注文作成**: 1秒以内
- **セッション作成**: 800ms以内

#### POS API
- **ポーリング**: 200ms以内
- **注文同期**: 1.5秒以内
- **メニュー同期**: 2秒以内

### 2.2 スループット

#### API処理能力
- **モバイルAPI**: 100 rps (同時ユーザー100人)
- **POS API**: 10 rps (ポーリングシステム)
- **管理画面**: 20 rps (同時管理者数人)

#### 注文処理
- **ピーク時**: 50注文/分 (ランチタイム等)
- **平常時**: 10注文/分

### 2.3 リソース使用量

#### サーバーリソース
- **CPU使用率**: 平常時 30%以下、ピーク時 70%以下
- **メモリ使用率**: 80%以下
- **ディスクI/O**: 1000 IOPS以下

#### データベース
- **接続数**: 最大100接続
- **クエリレスポンス**: 100ms以内 (90%タイル)
- **ロック待時間**: 5秒以内

## 3. 可用性要件

### 3.1 システム稼働率
- **目標**: 99.5% (1ヶ月あたり3.6時間のダウンタイムまで許容)
- **営業時間内**: 99.9%
- **メンテナンス時間**: 毎週日 AM 2:00-4:00

### 3.2 障害対応

#### 障害レベル定義
- **レベル1 (緊急)**: サービス全停止 - 30分以内復旧
- **レベル2 (重大)**: 主要機能不具合 - 2時間以内復旧
- **レベル3 (中)**: 一部機能不具合 - 4時間以内復旧
- **レベル4 (低)**: 軽微な不具合 - 次回メンテナンスで対応

#### 障害監視
- **監視間隔**: 1分毎
- **アラート通知**: メール + Slack
- **ヘルスチェックエンドポイント**: `/health`

### 3.3 バックアップと復旧

#### データバックアップ
- **フルバックアップ**: 毎日 AM 3:00
- **差分バックアップ**: 4時間毎
- **バイナリログ**: リアルタイムレプリケーション
- **保存期間**: 30日間

#### 復旧目標
- **RPO (Recovery Point Objective)**: 4時間 (最大データ損失)
- **RTO (Recovery Time Objective)**: 2時間 (最大復旧時間)

## 4. セキュリティ要件

### 4.1 認証・認可

#### パスワードポリシー
- **最小長**: 8文字
- **文字種類**: 英大文字、小文字、数字、記号を含む
- **有効期限**: 90日
- **履歴管理**: 過去5回と同じパスワード禁止

#### セッション管理
- **セッションタイムアウト**: 2時間 (管理画面)
- **APIトークン有効期限**: 24時間 (モバイル)、無期限 (POS)
- **同時ログイン**: 同一アカウントで3セッションまで

#### アクセス制御
- **IPアドレス制限**: POS APIは店舗固定IPのみ許可
- **レート制限**: 一般API 60回/分、POS API 120回/分
- **CORS設定**: 許可されたドメインのみ

### 4.2 データ保護

#### 暴号化
- **保存時暴号化**: パスワードはBcrypt、個人情報はAES-256
- **通信時暴号化**: HTTPS (TLS 1.2以上)
- **データベース**: at-rest暴号化対応

#### 個人情報保護
- **データ保持期限**: 2年間 (法的義務に基づく)
- **データ主体権利**: データの閲覧、修正、削除機能
- **ログマスキング**: ログ出力時の個人情報マスキング

### 4.3 セキュリティモニタリング

#### ログ監視
- **アクセスログ**: 全APIアクセスを記録
- **認証ログ**: ログイン成功/失敗を記録
- **エラーログ**: アプリケーションエラーを記録
- **ログ保存期間**: 1年間

#### 異常検知
- **ブルートフォースアタック**: 5回連続失敗でIPブロック (30分間)
- **SQLインジェクション**: 異常なクエリパターン検知
- **DDoS**: 短時間の大量アクセス検知

## 5. ユーザビリティ要件

### 5.1 アクセシビリティ

#### ウェブアクセシビリティ
- **準拠ガイドライン**: WCAG 2.1 AAレベル
- **スクリーンリーダー対応**: 適切なALTテキスト、ARIAラベル
- **キーボード操作**: Tabキーでのナビゲーション対応
- **コントラスト比**: 4.5:1以上 (通常テキスト)、3:1以上 (大きなテキスト)

#### 多言語対応
- **対応言語**: 日本語、英語、中国語繁体字、中国語簡体字、韓国語
- **文字エンコーディング**: UTF-8
- **日付・時間形式**: 各地域の慣習に合わせた形式

### 5.2 ユーザーインターフェース

#### レスポンシブデザイン
- **モバイルファースト**: スマートフォンでの操作を優先
- **ブレークポイント**: 320px以上のスマートフォン対応
- **タッチターゲット**: 最小44px×44px

#### 操作性
- **直感的な操作**: 初回利用者でも迷わないUI
- **エラーメッセージ**: ユーザーフレンドリーな表現
- **ローディング表示**: 1秒以上の処理には進行状況表示

## 6. 保守性要件

### 6.1 コード品質

#### コーディング標準
- **PSR準拠**: PSR-1, PSR-2, PSR-4に準拠
- **静的解析**: PHPStan (Level 8)、ESLint
- **コードカバレッジ**: 80%以上 (単体テスト)

#### ドキュメンテーション
- **APIドキュメント**: OpenAPI 3.0形式
- **コードコメント**: 複雑なロジックには必須
- **README**: 環境構築手順、デプロイ手順を記載

### 6.2 システム管理

#### ログ管理
- **ログレベル**: ERROR, WARNING, INFO, DEBUG
- **ログローテーション**: 日単位、最大100MB/ファイル
- **構造化ログ**: JSON形式で出力

#### 監視・アラート
- **メトリクス収集**: レスポンス時間、エラー率、スループット
- **アラート閾値**: レスポンス時間 > 5秒、エラー率 > 5%
- **エスカレーション**: 15分後にマネージャーに連絡

## 7. スケーラビリティ要件

### 7.1 水平スケーリング

#### Webアプリケーション
- **ロードバランサー**: Nginxで複数インスタンスに分散
- **セッション管理**: Redisクラスターで共有
- **ファイルストレージ**: S3互換ストレージ

#### データベース
- **リードレプリカ**: 参照クエリの分散
- **シャーディング**: 店舗IDベースの水平分割を検討
- **コネクションプール**: 適切なサイジ設定

### 7.2 垂直スケーリング

#### サーバースペック
- **現在**: 2vCPU, 4GB RAM, 50GB SSD
- **スケールアップ**: 4vCPU, 8GB RAM, 100GB SSD
- **最大**: 8vCPU, 16GB RAM, 200GB SSD

#### 自動スケーリング
- **CPU使用率**: 70%でスケールアップ、30%でスケールダウン
- **メモリ使用率**: 80%でスケールアップ
- **レスポンス時間**: 3秒以上でスケールアップ

## 8. 互換性要件

### 8.1 ブラウザー対応

#### サポートブラウザー
- **デスクトップ**: Chrome 100+, Firefox 100+, Safari 15+, Edge 100+
- **モバイル**: iOS Safari 15+, Android Chrome 100+
- **非サポート**: Internet Explorer

#### フォールバック
- **JavaScript無効**: 基本機能は利用可能
- **CSS無効**: 文字情報は読み取り可能

### 8.2 デバイス対応

#### スクリーンサイズ
- **スマートフォン**: 320px - 480px
- **タブレット**: 481px - 1024px
- **デスクトップ**: 1025px以上

#### 入力デバイス
- **タッチ操作**: スマートフォン・タブレット
- **キーボード操作**: PCブラウザー
- **マウス操作**: PCブラウザー

## 9. 法的要件

### 9.1 個人情報保護法

#### 収集する個人情報
- **お客様**: 氏名、メールアドレス (任意)
- **管理者**: 氏名、メールアドレス、電話番号
- **アクセスログ**: IPアドレス、User-Agent

#### 同意管理
- **管理者登録時**: 個人情報取扱同意取得
- **お客様情報登録時**: 任意情報の収集同意
- **Cookie使用**: Cookieポリシー表示と同意

### 9.2 アクセシビリティ法令
- **準拠法令**: 障害者差別解消法
- **対応レベル**: JIS X 8341-3:2016 AAレベル

## 10. 環境要件

### 10.1 システム構成

#### サーバー環境
- **OS**: Ubuntu 20.04 LTS以上
- **Webサーバー**: Nginx 1.18+
- **アプリケーションサーバー**: PHP 8.1+, Laravel 10+
- **データベース**: MySQL 8.0+
- **キャッシュ**: Redis 6.0+

#### コンテナ環境
- **コンテナ**: Docker 20.10+
- **オーケストレーション**: Docker Compose 2.0+ (開発環境)
- **プロダクション**: Kubernetes 1.24+ (将来的に検討)

### 10.2 外部サービス

#### 必須サービス
- **メール送信**: SMTPサービス (テスト環境ではMailpit)
- **ファイルストレージ**: S3互換ストレージ
- **SSL証明書**: Let's Encryptまたは有料SSL証明書

#### オプションサービス
- **CDN**: CloudFlare等のコンテンツ配信ネットワーク
- **監視サービス**: Uptime Robot等の外部監視
- **解析サービス**: Google Analytics 4 (管理画面のみ)

---

この非機能要件定義書に従ってシステムを設計・構築することで、安定した高品質なモバイルオーダーシステムを提供できます。各要件はプロジェクトの進行に合わせて継続的に見直し、更新していく必要があります。
