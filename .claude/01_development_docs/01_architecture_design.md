# アーキテクチャ設計書

## 1. システム概要

### 1.1 プロジェクト名
Mobile Order System（mobile-order）

### 1.2 システム目的
飲食店向けモバイル注文システム。お客様がQRコードをスキャンしてスマートフォンからメニューを閲覧・注文し、POSシステムと連携する汎用的なオーダーシステム。

### 1.3 技術スタック

#### バックエンド
- **フレームワーク**: Laravel 10.48.29
- **言語**: PHP 8.1+
- **データベース**: MySQL 8.0+
- **認証**: Laravel Breeze（管理者）+ ゲスト認証（モバイル）+ Laravel Sanctum（POS）

#### フロントエンド
- **フレームワーク**: Laravel Livewire 3.6+
- **JavaScript**: Alpine.js（Livewireにバンドル）
- **UIフレームワーク**: Mary UI v2.4+
- **CSS**: TailwindCSS 4.0
- **ビルドツール**: Vite 4.x

#### 開発環境
- **コンテナ**: Laravel Sail (Docker)
- **サービス**: MySQL, Redis, Mailpit, phpMyAdmin

## 4. 認証・認可設計

### 4.1 認証方式（3種類）

#### Laravel Breeze（管理者用）
- **対象**: 管理者、スーパーユーザー
- **方式**: Session/Cookie認証
- **機能**: ログイン、パスワードリセット、2FA対応

#### 2層認証システム（モバイル用）
**第1層: 席セッション認証**
- **対象**: QRコードから始まる席情報
- **方式**: データベースセッション管理（sessionsテーブル）
- **有効期限**: 3時間（席の利用時間）
- **目的**: 同席者間での注文履歴共有

**第2層: ゲストセッション認証**
- **対象**: 個人端末の識別
- **方式**: カスタムトークン + Redis
- **有効期限**: 30分（アクティビティで自動延長）
- **目的**: 個人識別・不正アクセス防止・端末特定

**協調動作による価値**
```
【席セッション】   【ゲストセッション】     【実現される価値】
QRコード読取  +    端末識別・認証    →    セキュアな個人注文
同席者共有   +    個人特定        →    注文者の明確化  
履歴管理     +    不正防止        →    安全な注文環境
```

#### Laravel Sanctum（POS用）
- **対象**: POSシステム
- **方式**: Bearer Token認証
- **有効期限**: 24時間（自動更新付き）
- **制限**: IPアドレス制限付き

### 4.2 認可設計
```php
// ユーザー役割
enum UserRole: string 
{
    case SUPER_ADMIN = 'super_admin';      // システム提供者
    case ADMIN = 'admin';                  // 店舗管理者
    case STAFF = 'staff';                  // 店舗スタッフ
    case POS_SYSTEM = 'pos_system';        // POSシステム
}

// 権限マトリクス
SUPER_ADMIN: 全機能アクセス可能
ADMIN: 店舗設定、メニュー管理、注文管理
STAFF: 注文確認、基本操作
POS_SYSTEM: データ同期、注文取得

// ゲスト（未登録ユーザー）: メニュー閲覧、注文送信（2層認証方式）
```

## 6. データベース設計方針

### 6.1 命名規則
- **テーブル**: snake_case複数形（`products`）
- **カラム**: snake_case単数形（`created_at`）
- **外部キー**: `{参照テーブル単数}_id`（`product_id`）

### 6.2 制約と整合性

## 12. カート管理設計

### 12.1 ハイブリッド方式
- **リアルタイム処理**: Redis（30分TTL、自動延長）
  - guest_session:{token} - セッション情報（スマホのみ）
  - guest_cart:{token} - カートアイテム（スマホのみ）
  - ハンディ端末はRedis使用なし（POS直接処理）
- **永続化**: cart_logsテーブル
  - 全操作履歴（add/remove/update/clear）
  - 操作時の価格・カート合計金額
  - エラー情報（error_code, error_message）
  - デバイス情報（fingerprint, IP, UA）
  - ハンディ端末は擬似トークンで記録

### 12.2 データ整合性
- **二重記録**: Redis障害時もDBログから復元可能
- **価格記録**: 操作時点の単価を保存
- **セッション紐付け**: session_idで席情報と連携
- **エラー追跡**: is_successフラグで成功/失敗を記録

### 12.3 調査・分析機能
- **トラブルシューティング**: ゲストトークンで操作履歴を追跡
  - スマホ: 実際のゲストトークン（guest_xxx）
  - ハンディ: 擬似トークン（handy_proxy_xxx）で識別
- **エラー分析**: error_codeごとの発生傾向
- **カート放棄分析**: 最終操作からの経過時間
- **売上分析**: cart_totalの推移から購買パターン把握
- **注文方法分析**: ゲストトークンプレフィックスで注文手段を識別

## 13. 翻訳サービス設計

### 13.1 翻訳アーキテクチャ
```
POS → Translation API → Dify Service → 並列翻訳処理 → Database更新
```

### 13.2 翻訳対象データ
- **商品（products）**: 商品名、商品説明
- **カテゴリ（categories）**: カテゴリ名
- **オプション（options）**: オプションタイトル

### 13.3 技術仕様
- **外部連携**: Dify経由で4言語並列翻訳
- **対応言語**: 英語、中国語繁体字、中国語簡体字、韓国語
- **処理方式**: 同期処理（全成功 or 全失敗）
- **タイムアウト**: 3-5分（商品数に応じて調整）
- **制限**: 最大10商品/リクエスト

### 13.4 エラーハンドリング
- **Dify障害時**: 既存翻訳データ返却
- **タイムアウト時**: 既存翻訳データ返却
- **データなし時**: 原文（日本語）返却

## 14. 管理ポータル権限設計

### 14.1 商品データ管理
- **方針**: 完全読み取り専用
- **理由**: POSシステムが商品マスター権限を持つ
- **機能**: 商品情報の閲覧・検索のみ

### 14.2 管理可能項目
- **Web固有設定**: テーマ、言語設定、通知設定
- **システム設定**: タイムゾーン、通貨設定
- **ユーザー管理**: 管理者アカウント管理
- **レポート**: 売上分析、商品分析（読み取り専用）

### 14.3 権限分離
```
POS側権限:
- 商品CRUD操作
- カテゴリCRUD操作
- オプションCRUD操作
- 価格・在庫管理

管理画面権限:
- Web設定管理
- ユーザー管理
- レポート閲覧
- 翻訳データ確認（読み取り専用）
```
