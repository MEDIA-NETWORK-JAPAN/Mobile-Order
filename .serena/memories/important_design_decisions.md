# Mobile Order System - 重要な設計判断

## アーキテクチャ設計

### POS中心設計
- **マスターデータ管理**: POS端末（Delphi + FireBird）が主体
- **クラウド側の役割**: POSからのデータ受信・表示（基本的にCUD操作は行わない）
- **データフロー**: POS → API → クラウド（一方向同期）
- **緊急時対応**: SuperAdminのみクラウド側で直接編集可能（POS障害時）

### 認証システム（3種類）
1. **お客様用2層認証**:
   - 第1層: 席セッション（QRコード、同席者間での注文履歴共有）
   - 第2層: ゲストセッション（個人識別、不正防止、端末特定）
2. **管理者認証**: Laravel Breeze（セッション/Cookie）
3. **POS認証**: Laravel Sanctum（Bearer Token）

### セッション管理（2層ハイブリッド方式）
- **席セッション（第1層）**: 
  - QRコード読み取り後の席管理
  - 固定モード: 無期限
  - 都度発行モード: 3時間TTL
- **ゲストセッション（第2層）**: 
  - 個人端末の識別管理
  - 30分TTL（アクティビティで自動延長）
  - データベース管理（guest_sessionsテーブル）

### カート管理（ハイブリッド方式）
- **Redisキャッシュ**: 高速アクセス用（30分TTL、自動延長）
- **DBログ**: 全操作履歴を永続化（cart_logsテーブル）
  - 成功/失敗フラグ
  - エラー情報記録
  - デバイス情報（fingerprint、IP、UA）

## データベース設計

### 統一商品マスター
- すべての商品を`products`テーブルで管理
- メイン商品、オプション商品、サイズ商品を統一管理
- 関連は`category_product`、`product_to_options`で構築

### マイナス価格対応
- 値引き商品のため価格フィールドはマイナス値を許可
- 価格計算時は負の値を考慮した処理

### 在庫状態管理
- `availability_status`: ENUM型で4状態管理
  - available: 利用可能
  - sold_out: 売り切れ
  - not_arrived: 未入荷
  - preparing: 準備中

### ソフトデリート
- 商品削除時はコード再利用対応
- `DELETED_{timestamp}_{元のコード}`形式で更新後にソフトデリート

## UI/UX設計

### ブラウザバック無効化
- 注文フロー中の誤操作防止のため実装
- JavaScript History APIを使用

### 管理画面UIパターン（Phase 2完了）
- **Index画面**: フィルター、ソート、ページネーション、権限別表示
- **Edit画面**: 3カラムUI（未割当 ← 操作 → 割当済み）
- **状態管理**: リダイレクト方式（プロパティリセットより確実）

### 多言語対応
- 日本語、英語、中国語（繁体/簡体）、韓国語
- Laravelの多言語機能を使用
- エラーメッセージも多言語対応

## 障害復旧設計

### POS障害時の運用継続
- クラウド単独で注文受付可能
- `cloud_synced`フラグで同期状態管理
- 復旧後の自動再同期機能

### ヘルスチェック
- 30秒間隔: 初期チェック
- 90秒間隔: 障害検知後の段階的チェック
- 自動復旧プロセス

### キャンセル処理
- 障害時は`canceled`ステータスで管理
- POS復旧後に適切な処理

## セキュリティ設計

### 管理画面URL隠蔽
- `ADMIN_URL_PREFIX`環境変数で管理画面URLを変更可能
- デフォルト: `/admin`
- 本番環境では必ず変更

### 権限管理
- SuperAdmin: 全機能アクセス可能（緊急編集含む）
- Admin: 通常管理機能（編集は制限あり）
- 閲覧のみ: データ閲覧のみ

### API認証
- POS連携: Bearer Token（Laravel Sanctum）
- 管理画面: セッション認証（Laravel Breeze）
- お客様: 2層認証（席セッション + ゲストセッション）
